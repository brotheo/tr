Robot Battery Monitor

Focus: WHILE
6 marks

A delivery robot starts with a battery level of 100%. Every time it moves forward, its battery drops by 10%. It should keep moving while its battery is greater than 20%.

Battery ← 100 decrease by 10 each move stop condition: Battery ≤ 20

Task

  1. Set the battery to 100.
  2. Repeatedly display the battery level.
  3. Display "Robot moving".
  4. Decrease the battery by 10.
  5. Stop when the battery is 20 or less.
  6. Display "Robot needs charging".

Example output

Battery: 100
Robot moving

Battery: 90
Robot moving

Battery: 80
Robot moving

...

Battery: 30
Robot moving

Robot needs charging
Write your pseudocode here.
Teaching note
Key idea: WHILE Battery > 20 — students must see that the condition is checked before each movement, not after.

Model structure

Battery ← 100

WHILE Battery > 20
    OUTPUT "Battery: ", Battery
    OUTPUT "Robot moving"
    Battery ← Battery - 10
ENDWHILE

OUTPUT "Robot needs charging"
02

Arcade Game: Keep Playing

Focus: WHILE + sentinel
7 marks

The player starts with Score ← 0 and enters the points earned after each round. Entering -1 means they want to stop playing.

Score ← 0 sentinel: -1 sentinel not added to score

Task

  1. Set the score to 0.
  2. Ask the player for points.
  3. Continue accepting points while the input is not -1.
  4. Add the points to the score.
  5. Ask for the next score.
  6. Display the final score.

Example output

Enter points: 20
Enter points: 50
Enter points: 30
Enter points: -1

Final score: 100
Write your pseudocode here.
Teaching note
Key idea: -1 is a sentinel value meaning "stop entering data" — it must never be added to the score. Watch for students who add it before checking.

Model structure

Score ← 0
INPUT Points

WHILE Points <> -1
    Score ← Score + Points
    INPUT Points
ENDWHILE

OUTPUT "Final score: ", Score
03

School Locker PIN

Focus: REPEAT...UNTIL + validation
5 + 2 marks

A school locker uses the 4-digit PIN 4729. The student enters a PIN; if it's wrong, the program asks again.

correct PIN: 4729 asks at least once

Task

  1. Ask the student to enter the PIN.
  2. Check whether it is correct.
  3. Continue asking until the correct PIN is entered.
  4. Display "Locker opened".

Example output

Enter PIN: 1234
Incorrect

Enter PIN: 5555
Incorrect

Enter PIN: 4729
Locker opened

Why is REPEAT...UNTIL a good choice here? (2 marks)

Your answer here.
Teaching note
Expected idea: the student must enter a PIN at least once, so a post-condition loop (REPEAT...UNTIL) fits — a WHILE loop would need an extra "priming" input before the loop.

Model structure

REPEAT
    OUTPUT "Enter PIN: "
    INPUT PIN
    IF PIN <> 4729 THEN
        OUTPUT "Incorrect"
    ENDIF
UNTIL PIN = 4729

OUTPUT "Locker opened"
04

Canteen Order System

Focus: REPEAT...UNTIL + validation
7 marks

The canteen menu is 1 = Burger, 2 = Pizza, 3 = Sandwich, 4 = Exit. The program should keep asking until the student enters a valid option from 1 to 4.

valid range: 1–4

Task

  1. Display the four options.
  2. Get the student's choice.
  3. Continue asking if the choice is invalid.
  4. Stop when a value from 1 to 4 is entered.
  5. Output "Order accepted".

Example output

1. Burger
2. Pizza
3. Sandwich
4. Exit

Enter choice: 8
Invalid choice

Enter choice: 0
Invalid choice

Enter choice: 2
Order accepted
Write your pseudocode here.
Teaching note
Key idea: the compound condition Choice >= 1 AND Choice <= 4 combined with REPEAT...UNTIL. Good place to check students don't invert the logic (looping while invalid vs. until valid).

Model structure

REPEAT
    OUTPUT "1. Burger"
    OUTPUT "2. Pizza"
    OUTPUT "3. Sandwich"
    OUTPUT "4. Exit"
    INPUT Choice
    IF Choice < 1 OR Choice > 4 THEN
        OUTPUT "Invalid choice"
    ENDIF
UNTIL Choice >= 1 AND Choice <= 4

OUTPUT "Order accepted"
05

Smart Classroom Temperature System

Focus: WHILE + sentinel + calculation
12 marks

A classroom temperature sensor sends readings. Entering -999 means the sensor has stopped. For every temperature: if it's greater than 30, output "Too hot", otherwise "Temperature OK". The program should also count how many readings were received.

sentinel: -999 threshold: > 30 count valid readings

Task

  1. Create a counter.
  2. Get the first temperature.
  3. Use a WHILE loop.
  4. Stop when -999 is entered.
  5. Count valid readings.
  6. Check whether each temperature is greater than 30.
  7. Get the next temperature.
  8. Display the number of readings.

Example output

Temperature: 25
Temperature OK

Temperature: 32
Too hot

Temperature: 29
Temperature OK

Temperature: 34
Too hot

Temperature: -999

Readings received: 4
Write your pseudocode here.
Teaching note
Key idea: this stacks three skills at once — sentinel-controlled WHILE, a nested IF for selection, and a running counter. Strong students should get the counter incrementing before the sentinel check, not after.

Model structure

Count ← 0
INPUT Temperature

WHILE Temperature <> -999
    Count ← Count + 1
    IF Temperature > 30 THEN
        OUTPUT "Too hot"
    ELSE
        OUTPUT "Temperature OK"
    ENDIF
    INPUT Temperature
ENDWHILE

OUTPUT "Readings received: ", Count
B

Bonus — Robot Warehouse

Focus: compound condition, two exit routes
12 marks

A warehouse robot starts with battery 100. After each movement the operator enters a command: F = forward, L = turn left, R = turn right, Q = quit. Each movement reduces the battery by 10. The robot keeps operating while the command is not Q and the battery is greater than 20.

Battery ← 100 exit 1: Command = "Q" exit 2: Battery ≤ 20

Expected behaviour

If the battery becomes 20 or less: display "Battery low" then "Robot stopped". If the operator enters Q: display "Operator stopped robot".

Write your complete pseudocode here.
Teaching note
Key idea: two independent reasons the loop can end. After the loop, students must test which condition caused the exit — Command = "Q" versus Battery <= 20 — and report the correct message. This is the step most students miss.

Model structure

Battery ← 100
INPUT Command

WHILE Command <> "Q" AND Battery > 20

    OUTPUT "Command: ", Command

    IF Command = "F" THEN
        OUTPUT "Moving forward"
    ENDIF

    IF Command = "L" THEN
        OUTPUT "Turning left"
    ENDIF

    IF Command = "R" THEN
        OUTPUT "Turning right"
    ENDIF

    Battery ← Battery - 10
    INPUT Command

ENDWHILE

IF Command = "Q" THEN
    OUTPUT "Operator stopped robot"
ELSE
    OUTPUT "Battery low"
    OUTPUT "Robot stopped"
ENDIF
